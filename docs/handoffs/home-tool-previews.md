# Homepage tool previews

## What changed

- Created `experiment/home-tool-previews` from clean `main` at `5cbf5c1`.
- Replaced the six icon-led tool treatments with screenshots of the actual tool
  interfaces, paired for light/dark mode. Titles, descriptions, destinations and NJ
  scope remain real text. Added a short example-view notice; screenshots are not a
  reader's results. All six cards remain direct links without prefetching.
- Kept three columns on desktop and two on smaller screens (verified down to 320px).
  Existing tool accents/glass surfaces, keyboard focus and reduced-motion support remain.
- Removed the visible “The national backdrop” heading. An accessible region name and
  screen-reader-only heading retain the United States scope and heading hierarchy.
  Reduced card padding, headline size and chart height together, retaining actual
  figures, source/date links, term explanations, trend captions and caveats.
- Search/map, Visual stories, section order, navigation, status and footer are unchanged.

## Files/modules affected

- `web/components/HomeTools.tsx`, `HomeTools.test.tsx`: extracted homepage tool cards,
  preview names and concise descriptions; both theme variants reuse `ThemedShot`.
- `web/app/page.tsx`: consume the tool component, remove visible national section
  heading and import homepage-only experimental styling.
- `web/app/home-tool-previews.css`: tool preview layout and compact national cards.
- `web/scripts/tool-previews.mjs`, `tool-previews.test.mjs`: six explicit content
  targets, deterministic sample inputs, readiness gates, themed JPEG captures and
  mocked runner/error-cleanup tests.
- `web/scripts/capture-readme.mjs`: integrate tool covers before homepage/README
  screenshots; serve just-generated tool images from disk during those captures.
  `SCREENSHOT_ONLY=tools` captures only the twelve tool images.
- `web/scripts/check-home-tool-previews.mjs`: responsive/theme/figure/a11y/navigation
  browser checks. `docs/DIRECTOR_NOTES.md`: append approved experimental direction.

## Architectural or implementation decisions

- No new client component, timer, library or API request for tool cards. Screenshots
  are decorative/lazy images; their real-text links remain useful without images.
- Extend the existing screenshot pipeline rather than commit bitmap assets. Twelve
  JPEGs are generated under `dist/artifacts/screenshots/tools/` (about 748 KiB total
  in this run, both themes combined). They live with the existing artifacts, not the
  Next page export; automatic refresh follows the existing screenshots/deploy target.
  No deployment or account/hosting change was performed.
- Capture only our own rendered UI. The tax preview deliberately uses an empty search
  interface: no parcel selected, no owner or residential-address record pictured.
- Use clean browser contexts, explicit $110,000 sample income, Princeton for the guide
  and Princeton/Montclair/Cherry Hill for comparison. The atlas uses a wider capture
  viewport so its map fits between the overlays. These are illustrative defaults,
  not personalised results or endorsed recommendations.
- Hide sticky navigation and the development indicator in captures, without changing
  source pages. Wait for interface-specific readiness and fail if the page/content
  cannot load; don't silently ship an empty tool screenshot.
- Keep all new CSS scoped to the homepage/unique preview classes and use existing
  colour tokens. No canonical project documents modified.

## Assumptions

- “Remove national backdrop” meant its visible heading, not its useful figures, as
  proposed and approved. National scope stays accessible without another visible line.
- Preview images are snapshots of the UI/data available at capture time, not a live
  mini-app. The real tool is reached by activating the card.
- The existing artifact publication/capture ordering remains responsible for serving
  the tool's aggregate JSON; this task does not alter data freshness or ingestion.

## New TODOs / limitations

- The twelve new covers must be generated by the updated screenshot pipeline before
  releasing this frontend. They are generated locally for review, not committed.
- Small screenshot text is illustrative, not a substitute for reading the tool. Card
  titles/descriptions are readable HTML, and the tax search is intentionally unfilled.
- Additional screenshot assets increase image transfer; lazy loading is retained.
  No deployed performance or low-end-device benchmarks were measured.
- Verification is local Chromium plus a scoped static production export, not a full
  site build/deploy or physical Safari/iOS/Android validation.
- No standalone frontend lint command is configured. TypeScript, colour-policy tests,
  Node syntax checks and whitespace validation were run instead. Python tests and
  `make publish`/`make check-dist` were not run for this frontend-only change; no live
  warehouse writes or ingestion performed. Full README/story screenshot capture was
  not rerun; its newly added tool-only path was exercised against the static build.
